## Как устроено участие

```steps
Выберите задачу :: Сначала оставьте в ней комментарий, чтобы двое не делали одно и то же.
Форк и ветка :: Работайте в своём форке, изменение должно быть небольшим и сфокусированным.
Запустите проверки :: Прогоните тесты проекта локально; CI повторит их в вашем pull request.
Откройте pull request :: Укажите, какую задачу он закрывает. Мейнтейнер проверит его и может попросить правки.
Слияние :: Принятые pull request сливаются через squash, так что в истории одно изменение — один коммит.
```

bitg просит подпись Developer Certificate of Origin в каждом коммите (`git commit -s`); его файл CONTRIBUTING шаг за шагом проводит через первый pull request.

## Как мы работаем

- **Письменно и асинхронно.** Решения принимаются в задачах и pull request, а не на созвонах. Участвовать можно из любого часового пояса.
- **На узбекском, русском или английском.** Пишите задачи и pull request на том из трёх языков, который вам удобнее.
- **Небольшие изменения.** Короткий pull request, который делает одно дело, проверяют быстрее большого.
- **Измеренные утверждения.** Если изменение что-то ускоряет или делает точнее, покажите цифру и то, как вы её получили.

## Вопросы

**Участникам платят?** Нет. Платной программы участия сегодня нет. Если это изменится, мы объявим здесь.

**Я новичок. Могу ли я помочь?** Да. Начните с одной из задач bitg с меткой good first issue; некоторые из них — правки документации или списков слов, где Rust вообще не нужен.

**Нужно ли знать узбекский?** Нет. Узбекский помогает с языковыми данными bitg, но код, тесты и документацию можно делать на английском или русском.

**Можно ли указать участие в резюме?** Да. Принятые pull request видны на GitHub под вашим именем.

**Есть ли собеседование или тестовое задание?** Сегодня нет, потому что нет процесса найма. Смотреть будут только на ваши pull request.
