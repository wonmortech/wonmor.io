## Что мы открываем по умолчанию

Мы предпочитаем делать репозиторий публичным, если это продукт или инструмент, который люди устанавливают или запускают, библиотека, которую могут использовать другие, или сайт, исходный код которого чему-то учит. У раннего открытия есть практическая польза: код может проверить любой, сканеры безопасности работают на нём бесплатно, а работа остаётся полезной, даже если мы остановимся.

У каждого публичного репозитория одинаковая база: файл code owners, политика безопасности организации, закрытые сообщения об уязвимостях GitHub (private vulnerability reporting) и защита от отправки секретов при push. Обновления Dependabot включены везде, кроме halvet, где их добавление в планах. Новые публичные репозитории сразу получают полную базу.

## Что остаётся закрытым и почему

Некоторые вещи не будут публичными, и лучше сказать об этом прямо, чем оставлять вас гадать:

- **Данные клиентов и пользователей.** Всё, что люди доверили нам хранить. Они никогда не попадают в репозиторий — ни в публичный, ни в закрытый.
- **Настройки инфраструктуры.** Адреса серверов, скрипты деплоя, схема сети и настройки мониторинга. Их публикация облегчает атаки и никому не помогает пользоваться продуктами.
- **Секреты.** Токены, ключи и пароли. Они хранятся в хранилищах секретов, а не в коде; коммиты с ними блокирует защита при push.
- **Код, который мы не вправе публиковать** или который ещё складывается. Несколько продуктов dtwin, включая основное приложение dtwin, сегодня находятся в закрытых репозиториях. Страница продукта ссылается на репозиторий, только если он публичный.

Закрытые репозитории подчиняются тем же инженерным правилам, что и открытые: pull request, CI и merge, который выполняет человек.

## Как внести вклад

Общий [CONTRIBUTING.md](https://github.com/dtwinuz/.github/blob/main/CONTRIBUTING.md) действует для всех репозиториев. Если в репозитории есть свой файл CONTRIBUTING, приоритет у него.

```steps
Issue :: для крупного изменения сначала откройте issue или возьмите существующий
Ветка :: от main, например feat/short-name или fix/short-name
Коммит :: в стиле Conventional Commits, например feat: или fix:
Pull request :: свяжите с issue, заполните шаблон, одна тема на PR
Ревью :: как минимум одно одобрение мейнтейнера и зелёный CI
Merge :: squash merge; после него ветка удаляется
```

Участники следуют кодексу поведения [Contributor Covenant 2.1](https://www.contributor-covenant.org/version/2/1/code_of_conduct/).

**Подпись и лицензионные соглашения.** Ни один репозиторий dtwin не просит подписывать лицензионное соглашение участника (CLA). Вместо этого bitg использует Developer Certificate of Origin (DCO): каждый коммит заканчивается строкой `Signed-off-by:` (`git commit -s`), а проверка в CI блокирует pull request без неё. Ваш вклад распространяется под лицензией репозитория; для bitg это MIT OR Apache-2.0. Остальные репозитории подпись пока не требуют.

**С чего начать.** bitg ждёт исправлений словаря и сообщений об ошибках с точным текстом, который вы набрали, и названием программы, в которой набирали. В его собственных [CONTRIBUTING.md](https://github.com/dtwinuz/bitg/blob/main/CONTRIBUTING.md) и [GOVERNANCE.md](https://github.com/dtwinuz/bitg/blob/main/GOVERNANCE.md) описано, как проверяются изменения, кто ведёт проект и как стать мейнтейнером.

## Сообщения о безопасности

Не сообщайте об уязвимостях в публичных issue, pull request или обсуждениях. Во всех публичных репозиториях из списка выше включены закрытые сообщения об уязвимостях GitHub: откройте вкладку Security репозитория и выберите «Report a vulnerability». Для закрытых репозиториев и работающих сайтов закрытый канал, сроки ответа и что указать описаны в нашей [политике безопасности](/ru/security/).
