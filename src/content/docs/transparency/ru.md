Доверие не должно держаться на том, что вы верите нам на слово. На этой странице — что мы публикуем о своей работе, когда публикуем, чего не опубликуем никогда и как проверить цифры выше своими инструментами.

Политика действует с 13 ноября 2026 года.

## Кто мы, если коротко

Wonmor — бренд из Узбекистана, который работает на собственные средства. Это не компания: нет юридического лица, совета директоров и инвесторов, и ни у кого за пределами Wonmor нет в нём финансовой доли. Серверы, домены, минуты CI и инструменты дизайна основатель оплачивает из своего кармана. Юридическое лицо и фонд открытого исходного кода в планах; когда одно из них станет реальным, об этом объявят с датой, а эта страница обновится.

Отчёт о поддержке пока в планах и ещё не опубликован. В нём будут перечислены виды расходов, которые покрывает Wonmor, например серверы, домены, CI и дизайн, и какие продукты они поддерживают. В нём будут реальные суммы по категориям, а не оценки.

## Чего мы не опубликуем никогда

Некоторые сведения закрыты намеренно и остаются закрытыми, даже если их публикация сделала бы какую-то цифру красивее:

- **Личные данные.** Имена, контакты, сообщения или активность любого, кто пользуется нашими продуктами.
- **Сведения о клиентах.** Кто использует продукт в коммерческих целях и всё, что касается их бизнеса, — если только они сами не попросили их назвать.
- **Секреты.** Токены, ключи, пароли и всё, что даёт доступ.
- **Детали инфраструктуры.** Адреса серверов, внутренние имена хостов и схема сети.
- **Неисправленные уязвимости.** Проблемы безопасности раскрываются только после выхода исправления, через advisory.

Если число нельзя показать, не раскрыв что-то из этого списка, мы его не показываем.

## Как проверить наши цифры

Большинство наших утверждений можно проверить с помощью GitHub CLI (`gh`) и двух публичных API. Сначала честная оговорка: часть наших репозиториев закрыта. Цифры выше мы считаем с доступом ко всем репозиториям организации, поэтому те же команды с вашего аккаунта покажут только публичную часть и вернут меньшие числа. В таких случаях публичное число — нижняя граница, которую вы можете проверить.

**Репозитории организации:**

```bash
gh repo list dtwinuz --limit 200 --json name --jq length
```

**Принятые pull request по всей организации:**

```bash
gh api "search/issues?q=org:dtwinuz+is:pr+is:merged" --jq .total_count
```

**Релизы проекта, например bitg:**

```bash
gh release list -R dtwinuz/bitg
```

**Что скачанный файл bitg собран из публичного исходного кода нашим релизным workflow:**

```bash
gh attestation verify bitg-0.3.1-x64.msi -R dtwinuz/bitg
```

**Уровень OpenSSF Best Practices для bitg:**

```bash
curl -s https://www.bestpractices.dev/projects/16620.json | jq .badge_level
```

**Результат OpenSSF Scorecard для bitg:**

```bash
curl -s https://api.securityscorecards.dev/projects/github.com/dtwinuz/bitg | jq .score
```

13 ноября 2026 года эти команды вернули 26 репозиториев и 639 принятых pull request (подсчёт с полным доступом), уровень бейджа bitg «gold» и оценку Scorecard 8,1. Цифры выше могут немного отличаться: они берутся во время сборки, а организация продолжает работать.

## Если цифра неверна

Если вы нашли на сайте цифру, которую не удаётся воспроизвести, или устаревшую, сообщите нам. Воспользуйтесь контактами на [странице безопасности](/ru/security/) или откройте публичный issue на [github.com/dtwinuz/.github](https://github.com/dtwinuz/.github/issues). Ошибки мы исправляем публично: исправленная страница получает новую дату обновления, а если ошибка была в новости, в посте сказано, что изменилось.
