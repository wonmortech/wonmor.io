Halvet — концепт-сайт для строителей хаммамов, саун и бассейнов. Его аудитория ждёт ощущения дороговизны: медленного кинематографичного движения, пара над тёплым камнем. В первой версии всё это было, и на телефоне ею почти невозможно было пользоваться. Мобильный профиль Lighthouse дал ей оценку производительности 55: Total Blocking Time 14,4 секунды, вес страницы 3,6 МБ.

Через один релиз, 9 ноября 2026 года, та же страница получила 100: Total Blocking Time ноль, страница 0,65 МБ. Следующий релиз добавил туман на WebGL-шейдере и сцену на three.js и всё равно получил 99 на мобильных и 100 на десктопе. Эта статья — о том, как это получилось, и о честном финале: оценка — не кубок, который остаётся у тебя навсегда.

```steps
Измерить :: Запустите Lighthouse в мобильном профиле и читайте диагностику, а не только оценку.
Найти одну причину :: Почти все 14,4 с блокировки давал один полноразмерный canvas с паром.
Удешевить :: Рисуйте эффект в доле разрешения и частоты кадров, только когда он виден и только после загрузки.
Срезать байты :: Адаптивный WebP, свои шрифты и неизменяемый кеш уменьшили страницу с 3,6 до 0,65 МБ.
Добавлять вау лениво :: Тяжёлые эффекты грузятся только по необходимости, сначала проверяют WebGL и всегда имеют дешёвый запасной вариант.
```

## Вся проблема была в одном эффекте

Герой — фотография хаммама, по которой плывёт пар. В v1 этот пар был 2D-canvas: 26 мягких спрайтов, перерисовываемых в каждом кадре анимации, с плотностью пикселей до 1,5×, наложенных на фотографию через `mix-blend-mode: screen`.

По отдельности каждая часть была разумной. Вместе, на замедленном телефоне среднего класса, это была катастрофа. Полноразмерный canvas величиной с экран очищался и перерисовывался шестьдесят раз в секунду, а затем в каждом кадре смешивался с изображением под ним, и это держало занятыми главный поток и композитор с самой первой отрисовки. Lighthouse засчитывает в Total Blocking Time каждую длинную задачу после первой отрисовки, и почти все 14,4 секунды давал этот цикл.

Исправление в v1.1 сохранило эффект и изменило его цену:

```js
var Q = 0.35;   // draw at 35% resolution: steam is soft, nobody can see the difference
var size = function () {
  W = cv.clientWidth; H = cv.clientHeight;
  cv.width = Math.ceil(W * Q); cv.height = Math.ceil(H * Q);
  ctx.setTransform(Q, 0, 0, Q, 0, 0);
};
var tick = function (t) {
  if (!visible || document.hidden) { looping = false; return; }   // stop offscreen and in background tabs
  requestAnimationFrame(tick);
  if (t - last < 33) return;                                       // about 30 fps is plenty for steam
  last = t;
  // ... draw puffs
};
// start 400 ms after the load event, so it never competes with the first paint
window.addEventListener('load', function () { setTimeout(startSteam, 400); });
```

Режим наложения убрали совсем, а спрайт перерисовали как скопление мягких пятен, чтобы обычная альфа хорошо смотрелась поверх фото. На узких экранах эффект использует 9 облаков вместо 18. Пар размыт по природе, поэтому отрисовка в 35% разрешения с растяжением незаметна глазу и стоит около одной восьмой пикселей canvas с плотностью 1×.

## Байты, шрифты и кеш

Когда главный поток освободился, осталась работа над весом:

- **Адаптивный WebP.** Каждая фотография, бывшая JPEG на 0,3–0,8 МБ, стала `srcset` из WebP шириной от 640 до 2000 пикселей, которые небольшой скрипт генерирует из исходников. Телефон загружает версию 640 или 1024.
- **Свои шрифты.** Шрифты переехали с Google Fonts на сам сайт, с `preload` для двух начертаний первого экрана; фотография героя тоже загружается заранее, с `fetchpriority="high"`. Это убрало стороннее соединение с критического пути и позволило полностью исключить Google из политики безопасности контента.
- **Неизменяемый кеш.** CSS и JavaScript подключаются как `styles.css?v=<commit>` и отдаются с долгим неизменяемым кешем, поэтому вернувшийся посетитель ничего не скачивает, а деплой всё равно инвалидирует всё.

В тот же релиз вошли основы для поисковиков: `robots.txt`, карта сайта, canonical-ссылка и теги Open Graph подняли категорию SEO с 92 до 100.

Тот же релиз сократил и текст. Подзаголовок над героем, подстрочник и несколько описаний карточек убрали не ради производительности, но страница стала легче и для загрузки, и для чтения.

## Возвращаем вау

Часть «без потери вау» проверялась в v1.2. Он добавил туман героя, написанный как WebGL-шейдер (два слоя шума с искажением координат, лучи света из проёмов купола, след курсора, который толкает туман), и сцену купола на three.js с настоящей фотографией, спроецированной на полусферу. Оценка всё равно осталась 99 на мобильных и 100 на десктопе. Это стало возможным благодаря трём правилам.

**Грузите тяжёлый код, только когда его вот-вот увидят.** Сцена three.js — отдельный чанк, который динамически импортируется, когда её раздел оказывается в 600 пикселях от области просмотра:

```js
var glOk = (function () { try { var c = document.createElement('canvas');
  return !!(c.getContext('webgl2') || c.getContext('webgl')); } catch (e) { return false; } })();
var saveData = navigator.connection && navigator.connection.saveData;
if (glOk && !saveData) {
  new IntersectionObserver(function (e, o) {
    if (!e[0].isIntersecting) return; o.disconnect();
    import('./dome.js?v=' + VER).then(function (m) { return m.mountDome(domeFig, dome, { reduce: reduce }); });
  }, { rootMargin: '600px 0px' }).observe(domeFig);
}
```

**Проверяйте, прежде чем тратить.** Нет WebGL или в браузере включён флаг Save-Data — посетитель видит фотографию и вообще не скачивает three.js.

**Всегда держите запасной вариант.** Если шейдер тумана не запустился или его WebGL-контекст потерян, страница снимает WebGL-класс и вместо него запускает дешёвый 2D-пар из v1.1. При `prefers-reduced-motion` туман рисуется неподвижной картинкой, а декоративное движение пропускается.

## Одна ловушка: CSP и инлайн-стили

В v1.3 вышла многослойная диаграмма, которая задавала CSS-переменную каждому слою через инлайн-атрибут `style="..."`. На локальном сервере она работала, а на живом сайте сломалась: в политике безопасности контента продакшена стоит `style-src 'self'`, которая блокирует инлайн-атрибуты style. Исправление — нумеровать слои через `:nth-child` в таблице стилей или задавать переменную из JavaScript через `style.setProperty`, что CSP разрешает. Теперь после каждого деплоя мы открываем консоль браузера на живом сайте.

## Ограничения: 100 — не навсегда

Оценка — снимок страницы в определённый день, а страница продолжала расти. v1.8 заменил туман GPU-симуляцией жидкости — паром, поднимающимся из курн. Компиляция её шейдеров блокировала главный поток, поэтому инициализация идёт по этапам: шейдеры компилируются в фоне через расширение `KHR_parallel_shader_compile`, а симуляция прогревается порциями примерно по шесть миллисекунд, чтобы ни одна задача не затягивалась. После этого релиза живой сайт показал 92 на мобильных: Largest Contentful Paint 2,8 с, Total Blocking Time 210 мс.

13 ноября 2026 года мы снова запустили Lighthouse 12.8.2 с настольной рабочей станции на живой сайт в стандартном мобильном профиле. Он показал производительность 78, доступность 96, лучшие практики 100 и SEO 100: Largest Contentful Paint 2,9 с, Total Blocking Time 550 мс, без сдвигов вёрстки, передано 795 КиБ. Лабораторные оценки меняются вместе с машиной, сетью и собственным разбросом Lighthouse; страница с тяжёлой GPU-нагрузкой колеблется сильнее большинства. Вывод, который мы сделали, — не «получи 100», а «знай, сколько стоит каждый эффект, и плати за него только тогда, когда посетитель смотрит».

Доступность намеренно остаётся на 96–97: управляемый прокруткой текст по мере чтения переводит слова из тусклых в яркие, и тусклые слова не проходят проверку контраста, пока не загорятся.
