Как сделать бренд-фильм из кода

Как 19,4-секундный бренд-фильм wonmor генерируется из одного файла таймлайна: canvas-рендерер для MP4, сгенерированный проект After Effects, Blender для материалов, синтезированный звук и кодирование для веба.

13 ноября 2026 · 4 мин чтения

На этой странице

  1. Почему фильм, а не живая анимация

  3. Размытие движения и почему каждая склейка привязана к кадру

  5. Кодирование для веба

Главный экран wonmor.io — бренд-фильм длиной 19,4 секунды. Один бриллиант разрезается, его нижняя часть становится буквой V, а V удваивается в W знака, после чего прорисовывается словесный знак. Видеоредактора в этом процессе нет. Фильм генерируется из одного JavaScript-файла, который описывает каждый слой и ключевой кадр, и тот же файл создаёт редактируемый проект After Effects. В этой статье — как это устроено и почему мы сделали именно так. Первая версия вышла 13 ноября 2026 года.

Почему фильм, а не живая анимация

Первым главным экраном была живая сцена: SVG-фигуры и таймлайн GSAP в браузере, а для бриллианта — сцена на three.js. Когда мы покадрово сравнили её с тем бренд-фильмом, к которому стремились, вывод был такой: главный экран должен быть заранее отрендеренным видео. Живая сцена доставляла проблемы и при записи: в headless-захвате с программным WebGL появлялись кадры-«призраки», где одновременно видны два состояния SVG-пути, хотя в настоящем окне Chrome всё было чисто. Бренд-момент должен выглядеть одинаково на любом экране, а запись — совпадать с тем, что мы видим.

Заранее отрендеренный фильм это решает, но фильм из видеоредактора создаёт другую проблему: исходник превращается в файл проекта, который открывает только одна программа, а любое изменение геометрии означает ручную переделку ключевых кадров. Мы хотели, чтобы фильм оставался кодом, читался в диффе и пересобирался одной командой, и при этом давал моушн-дизайнеру настоящий проект After Effects.

Один таймлайн, три рендерера

timeline.mjs — единственный источник истины. Он строит список слоёв (заливки, шейп-слои, группы, последовательности изображений, слой зерна) с ключевыми кадрами и именованными кривыми и записывает его в JSON для двух форматов, 9:16 и 16:9. Геометрия знака берётся из общего модуля, который определяет логотип, поэтому фильм не может разойтись с брендом.

План в таймлайне читается так. Вот фон — один слой, цвет которого переключается с hold-кривой на каждой границе плана:

const BG = [
  [0, K.ink], [4.60, K.ink], [5.57, K.paper], [6.57, K.ink], [11.07, K.paper], [12.07, K.ink],
  [15.57, K.blue], [16.07, K.ink], [16.57, K.paper], [18.13, K.blue], [18.93, K.ink],
];
L({ type: 'solid', name: 'BG', w: Wd, h: Hd, color: kf(...BG.map(([t, c]) => [t, c, E.hold])) });

Этот JSON читают три потребителя:

  • Canvas-плеер (comp/player.js) рисует любой момент t фильма. Инструмент захвата открывает его в headless Chromium через Playwright, рендерит кадр за кадром, делает PNG-скриншот каждого и передаёт в ffmpeg (-f image2pipe, libx264, CRF 12) для мастера.
  • Генератор After Effects (tools/ae.mjs) пишет ExtendScript-файл, который пересобирает обе композиции из тех же данных: редактируемые шейп-слои с ключевыми кадрами и кривыми, последовательности изображений с ремапом времени, подложки, звук и маркеры планов.
  • Набор для Figma берёт по одному ключевому кадру из каждого из 28 планов фильма и раскладывает их как раскадровку.

Поскольку все три читают одни и те же числа, изменение кривой или времени склейки в таймлайне одинаково проявляется и в MP4, и в проекте After Effects.

Размытие движения и почему каждая склейка привязана к кадру

Моушн-графика без размытия движения выглядит как запись экрана. У canvas нет затвора, поэтому плеер его имитирует: для каждого выходного кадра он рисует несколько подкадров на интервале в половину кадра (затвор 180°) и усредняет пиксели.

// average sub-frames over a 180 degree shutter (half a frame interval)
for (let s = 0; s < samples; s++) {
  draw(octx, t + (s / samples) * (0.5 / timeline.fps));
  const d = octx.getImageData(0, 0, off.width, off.height).data;
  for (let i = 0; i < d.length; i++) acc[i] += d[i];
}

При четырёх сэмплах 582 кадра фильма (19,4 с при 30 fps) означают 2 328 полных отрисовок. Это медленно, но для офлайн-рендера нормально.

Отсюда появился один баг, который стоит записать. Если склейка попадает между началами двух кадров, часть подкадров берётся из уходящего плана, часть — из приходящего, и среднее смешивает два несвязанных изображения в кадр с «призраком». Исправление живёт в таймлайне, а не в рендерере. Перед записью JSON время входа и выхода каждого слоя и каждый ключевой кадр округляются до начала кадра:

const q = (t) => Math.round(t * FPS) / FPS;

После этого подкадры всегда попадают внутрь одного плана.

Материалы из Blender, звук из Python

Некоторым планам нужны настоящие материалы: небольшой синий стеклянный бриллиант, металлический знак, несколько 3D-сцен. Они рендерятся в Blender движком Cycles на процессоре из сцены, описанной скриптом, по одному плану, с 48–128 сэмплами в зависимости от плана. На выходе — последовательности изображений, которые таймлайн расставляет как любой другой слой. Бриллиант, например, — это бесшовное вращение из 31 кадра, поэтому его можно зацикливать сколько нужно плану. Полный проход Blender занимает около двадцати минут на процессоре. Всё остальное — вектор и рендерится в браузере.

Звук тоже синтезирован, без сэмплов. Скрипт на Python с NumPy собирает стереодорожку 48 кГц по меткам времени, совпадающим с таймлайном, а фильтр громкости ffmpeg нормализует её до -16 LUFS. Когда склейка сдвигается, звук не перемонтируют, а генерируют заново.

Кодирование для веба

Финальный скрипт сводит звук и выпускает три вещи: мастер высокого качества с AAC 320 кбит/с, веб-версии для каждого соотношения сторон и постер, снятый на 11,5 секунде. Веб-версия кодируется x264 с CRF 24, -tune film, адаптивным квантованием в режиме 3, масштабированием Lanczos и +faststart, чтобы воспроизведение начиналось до окончания загрузки файла. Звук сохранён на 128 кбит/с: на старте страница проигрывала фильм без звука по умолчанию, с кнопками звука и паузы.

Сегодня опубликованный файл 16:9 весит 2 656 349 байт: 1920×1080, 30 fps, H.264 с AAC, ровно 19,4 секунды.

Ограничения

  • Рендер офлайн и медленный. Изменение одной кривой означает перерендер всех кадров с размытием движения, а если меняется материальный план — ещё и Blender. Это пакетная задача, а не живой предпросмотр.
  • Проект After Effects точный, но не полностью нативный. Векторные слои приходят редактируемыми фигурами с настоящими ключевыми кадрами, а планы из Blender — последовательностями изображений. Чтобы изменить бриллиант, нужно вернуться в Blender.
  • Фильм не может реагировать. Живая сцена может отвечать на курсор и прокрутку, фильм — нет. Для бренд-момента мы принимаем этот компромисс.
  • Релизных файлов нет в репозитории. Мастер и архивы для After Effects и Figma — результаты сборки, git их игнорирует, поэтому для передачи их нужно сгенерировать заново или хранить в другом месте.

Повторите сами

Проверьте опубликованный фильм сами: длительность, размер кадра, частота кадров и кодеки берутся прямо из файла на wonmor.io.

$ ffprobe -v error -show_entries format=duration,size:stream=codec_name,width,height,r_frame_rate -of compact https://wonmor.io/film/wonmor_16x9.mp4
